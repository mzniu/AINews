# AINews UX 优化方案

> 落盘日期：2026-06-26
> 范围：主页（`static/index.html`）、GitHub 视频向导（`static/github_video_maker.html`）、导航四页面整体一致性
> 方法：启发式评估 + 用户旅程分析（基于代码静态盘点，未做真实用户测试，结论需后续 5-8 人可用性测试验证）

## 关键发现

### 1. 主页是「单页长表单」，缺步骤推进感
主页把 **抓取输入 → 抓取结果 → 内容编辑 → 4 个图片增强面板 → 口播字数 → AI 摘要 → 排序 → 配音字幕 → 视频生成** 全部堆在一个垂直滚动里（`static/index.html:30-330+`）。用户从哪儿开始、到哪儿结束、当前在第几步，全无视觉锚点。

**对照**：`github_video_maker.html:35-41` 已有清晰的 5 步 `step-indicator`——这是项目里被验证过的模式，应该反向迁移到主页。

### 2. 编辑区「图片增强」4 个面板信息密度过载
`index.html:133-186` 纵向堆了 4 个并列面板：
- 上传本地图片/视频（生产功能）
- AI 封面图 Seedance（生产功能，需 API key）
- 网页搜图百度（**开发用**，UI 上自己写了"开发用"）
- 全网补充图 DeepSeek（生产功能，参数最多）

4 个面板都展开时，一屏几乎装不下，且「开发用」和「生产」功能混在一起。普通用户面对 4 套不同参数表单会直接弃用。

### 3. 主操作按钮优先级混乱
`index.html:200-210` 有 3 个并列按钮：生成AI标题和摘要、🚀 一键生成视频、重置选择；后面 `index.html:313-325` 又有 生成视频 / BGM / 保存修改 / 分析GIF。用户不知道该先点哪个，"一键"和"分步"两条路径同时存在无引导。

### 4. 错误反馈方式不统一
- `static/js/index/main.js` 多处用 `alert('请先输入或编辑文章内容')`——阻塞、丑、移动端体验差。
- `index.html:87` 有 `<div class="error" id="error">` 但只用于抓取阶段。
- 又有 `showToast`（main.js 多处）。
- 三套机制并存，用户不知道错误会以什么形式出现。

### 5. Loading 状态用 input 占位文字
`main.js` 用 `input.value = '正在生成…'` 当 loading。无 skeleton、无 spinner、无进度条。GitHub 向导 `github_video_maker.html:80-84` 有 spinner+status 文案——又是可复用的现成模式。

### 6. AI 摘要面板字段过多、无分组
`index.html:216-311` 一屏堆叠：主标题第一行+8 色板、第二行+8 色板、字体字号、副标题、摘要、口播稿、标签、methodology insight、meta、show_summary 开关、BGM、保存/分析/生成。**主标题两行的 8 色色板每个占 ~120px 高**，两次就是 240px 纯色板——这是最高频改的字段吗？大概率不是。

### 7. 新增 methodology insight 缺解释
`index.html` 紫色条显示「🎯 目标受众 | 💬 夸赞点」，但没说这是什么、为什么不可编辑、对用户有什么用。用户会以为是装饰。

### 8. 跨页面命名/视觉不一致
- `<title>` 是"网页内容抓取工具"（`index.html:6`），但 nav 里叫"🏠 主页"（`index.html:16`），`<h1>` 又是"🌐 网页内容抓取工具"（`index.html:26`）。三个名字。
- nav 四个 link 的 emoji 风格不统一，active 状态视觉差异弱。

## 优化建议（按优先级）

### 🔴 P0 高优先

#### P0-1. 主页改为 5 步向导，复用 GitHub 向导的 step-indicator 【暂缓】
- 步骤：① 输入内容 → ② 选素材 → ③ 生成 AI 文案 → ④ 排序与配音 → ⑤ 生成视频
- 直接复用 `github_video_maker.html:35-41` 的 `step-indicator` 组件 + CSS。
- 一键生成视频按钮保留，但改为"跳过 ③ ④ 直接走完全流程"的快捷入口，文案改"🚀 极速模式（自动跳过中间步）"。
- **预期收益**：用户旅程可视化，跳出率应明显下降。

#### P0-2. 图片增强 4 面板折叠为高级折叠
- 默认只展开"上传本地图片/视频"；其余 3 个收进 `<details>`。
- "网页搜图（开发用）"移到 dev 模式开关后，生产环境默认隐藏。
- **预期收益**：编辑区垂直高度缩短 ~60%，主路径用户不被支线功能干扰。

#### P0-3. alert → toast 全面替换
- `main.js` 里所有 `alert(...)` 改为现有 `showToast(msg, 'error')`；`'info'/'success'` 已有就复用。
- 估算 5-8 处替换，零新增依赖。

#### P0-4. 主操作按钮分层
- 主路径只有 **1 个主按钮**（生成AI文案 → 下一步 → 排序 → 生成视频）。
- "重置选择""分析GIF""保存修改"降级为次按钮或溢出菜单。
- 视觉上 Primary / Secondary / Tertiary 三级清晰。

### 🟡 P1 中优先

#### P1-1. 主标题色板默认收起
- 8 色色板放进"🎨 颜色"折叠触发器，默认用白字。需要改色时点开。
- 释放 ~240px 垂直空间给真正高频的字段（标题文本、摘要）。

#### P1-2. AI 摘要面板分组
- 分 3 组：① 标题区（L1/L2/字体/副标题）② 文案区（摘要/口播稿/标签）③ 元数据区（methodology insight / meta / 高级开关）。
- 每组一个轻量卡片，可折叠。

#### P1-3. methodology insight 加 1 句解释
- 紫条上方加 12px 灰字："AI 推断的受众与夸赞点，用于指导标题写作；不可编辑，重新生成会刷新。"

#### P1-4. Loading 统一为 spinner + 状态文案
- 复用 `github_video_maker.html:80-84` 的 `.loading > .spinner + p + small` 结构。
- 长任务（抓取、AI 生成、视频合成）显示进度文案，不用 input value 占位。

### 🟢 P2 长期

#### P2-1. 统一设计系统
- 抽 `static/css/tokens.css`：颜色、字号、间距、圆角变量。
- nav 四页面共用，消除 inline style。
- 这是技术债治理，UX 收益是「跨页面视觉一致性」。

#### P2-2. 真实用户可用性测试
- 招 5-8 名目标用户（AI 从业者/内容创作者），给 3 个任务：抓新闻做视频、GitHub 项目做视频、改标题配色。
- 录屏 + 出声思考，量化任务完成率/时长/卡点。
- 用真实数据校准本方案的启发式猜测。

#### P2-3. 移动端适配审计
- 现有 viewport meta 有了，但表格、排序面板、AI 摘要面板在窄屏的可用性未验证。
- 排序面板已有 `min(560px, calc(100vw - 40px))` 是好开始，其他面板要跟进。

## 现有的好设计（不要拆掉）

- **GitHub 向导的 5 步 step-indicator**（`github_video_maker.html:35-41`）——可直接复用到主页。
- **媒体选择器悬浮预览**（`main.js` 的 `_attachMediaSelectorHover`）——刚加，等实测。
- **排序面板三行卡片 + 数量徽章 + 总时长**（`index.html` 排序面板、`index.css` 的 `.sort-item-row-*`）——刚重构成 flex 三行，待实测。
- **GitHub 向导的 spinner+status loading**（`github_video_maker.html:80-84`）——可全项目复用。

## 成功指标

| 指标 | 当前 | 目标 | 测量方式 |
|---|---|---|---|
| 主页首屏找到"下一步该点哪"时长 | 未知（疑似高） | < 5 秒 | 5-8 人测试 |
| 完整跑通"抓新闻→生成视频"任务完成率 | 未知 | ≥ 85% | 同上 |
| alert 调用数 | ~8 处 | 0 | 代码 grep |
| 主页垂直滚动距离（首屏到生成视频按钮） | ~3-4 屏 | ≤ 2 屏 | 改造后量 |

## 不做（Non-goals）

- 不动后端 API 结构、不动内容方法论 prompt（刚调好）。
- 不引入 React/Vue 等前端框架（项目是原生 JS，重写成本不值）。
- 不做用户账号系统（除非后续明确需要）。
